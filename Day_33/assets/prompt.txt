Um den Router srv-rocky als zentralen DNS-Server für das gesamte Labornetzwerk einzurichten, nutzen wir den bewährten DNS-Server BIND (named). Er wird so konfiguriert, dass er die neue Domäne tobias.lan verwaltet, die Subdomains für Netz A und Netz B auflöst und alle externen Anfragen an einen Upstream-DNS (z. B. 8.8.8.8) weiterleitet.

Da du die Geräte entsprechend benennen möchtest, mappen wir die Subdomains wie von dir gewünscht.

Hinweis zur Namensgebung: Du hast für beide Netze netz1.tobias.lan geschrieben. Um die Netze sauber zu trennen und IP-Überschneidungen im DNS zu verhindern, konfigurieren wir Netz A als netz1.tobias.lan und Netz B als netz2.tobias.lan. Wenn beide absolut identisch heißen müssen, können sie auch in dieselbe Zonendatei geschrieben werden – die Trennung in netz1 und netz2 ist jedoch Best Practice zur Vermeidung von IP-Konflikten.

🛠️ 1. Installation und Basis-Konfiguration auf srv-rocky
Führe diese Schritte direkt auf dem Rocky Linux Router aus.

Bash
# Installation des BIND DNS-Servers und der Utilities
sudo dnf install -y bind bind-utils

# Hauptkonfigurationsdatei öffnen
sudo nano /etc/named.conf
Ersetze oder ergänze die Optionen in der /etc/named.conf wie folgt, damit BIND auf allen internen Schnittstellen lauscht und Anfragen weiterleitet:

Code-Snippet
options {
        listen-on port 53 { any; };
        listen-on-v6 port 53 { none; };
        directory       "/var/named";
        dump-file       "/var/named/data/cache_dump.db";
        statistics-file "/var/named/data/named_stats.txt";
        memstatistics-file "/var/named/data/named_mem_stats.txt";
        secroots-file   "/var/named/data/named.secroots";
        recursing-file  "/var/named/data/named.recursing";

        # Erlaubt Abfragen aus den internen Netzen
        allow-query     { localhost; 172.16.7.0/24; 192.168.1.0/24; }; # Passe die Subnetze ggf. an

        # Weiterleitung fuer externe Domains (z.B. Internet)
        recursion yes;
        forwarders {
                8.8.8.8;
                8.8.4.4;
        };

        dnssec-validation yes;
        managed-keys-directory "/var/named/dynamic";
        pid-file "/run/named/named.pid";
        session-keyfile "/run/named/session.key";
};

logging {
        channel default_debug {
                file "data/named.run";
                severity dynamic;
        };
};

# Definition der Hauptzone tobias.lan
zone "tobias.lan" IN {
        type master;
        file "zones/db.tobias.lan";
        allow-update { none; };
};

🔒 3. Rechte, Firewall und Dienst-Start
Damit BIND die Dateien lesen kann und der Port blockierungsfrei erreichbar ist, müssen die SELinux/Dateirechte sowie die Firewall angepasst werden.

Bash
# Dateirechte an den BIND-User (named) uebergeben
sudo chown -R named:named /var/named/zones

# Konfiguration auf Syntaxfehler pruefen (wichtig!)
sudo named-checkconf /etc/named.conf
sudo named-checkzone tobias.lan /var/named/zones/db.tobias.lan

# DNS-Port (53/udp und 53/tcp) in der Firewall freigeben
sudo firewall-cmd --add-service=dns --permanent
sudo firewall-cmd --reload

# Dienst aktivieren und starten
sudo systemctl enable --now named

Die Ausgabe zeigt, dass srv-debian-02 aktuell noch den Cloudflare-DNS (1.1.1.1) statt deines Routers srv-rocky abfragt. Da öffentliche DNS-Server deine lokale Domäne .lan nicht kennen, wird die Anfrage mit NXDOMAIN abgelehnt. Zudem liegt srv-deb-01 laut Netzplan in netz1 (Netz A), nicht in netz2.

Da deine VMs ihre IPs dynamisch beziehen, überschreibt die DHCP-Konfiguration des Routers bei jedem Lease die lokalen Einstellungen der Clients. Die DNS-Verteilung muss daher zentral auf srv-rocky korrigiert werden.

1. DHCP-Server auf srv-rocky anpassen
Je nachdem, welchen DHCP-Server du auf dem Rocky-Router installiert hast, musst du die Nameserver-Option auf die jeweilige Schnittstellen-IP des Routers umbiegen:

Falls dhcpd (ISC DHCP Server) aktiv ist:
Öffne die /etc/dhcp/dhcpd.conf und passe die Zeilen in den Subnet-Blöcken an:

Plaintext
subnet 172.16.7.32 netmask 255.255.255.224 {
    # ... andere Optionen ...
    option domain-name-servers 172.16.7.33;
    option domain-search "tobias.lan";
}

subnet 172.16.7.96 netmask 255.255.255.224 {
    # ... andere Optionen ...
    option domain-name-servers 172.16.7.97;
    option domain-search "tobias.lan";
}
Falls dnsmasq aktiv ist:
In der /etc/dnsmasq.conf oder im entsprechenden Konfigurationsfile:

Plaintext
dhcp-option=option:dns-server,172.16.7.33,172.16.7.97
Starte den DHCP-Dienst danach auf srv-rocky neu (z. B. sudo systemctl restart dhcpd).

kann ich den dns eintrag noch mit txt "aufbohren"?

Ja, du kannst den DNS-Eintrag deiner Domäne mit TXT-Records (Text Records) erweitern. In einem lokalen Labornetzwerk werden TXT-Records häufig genutzt, um Beschreibungen, Server-Rollen oder Konfigurationsdaten für Anwendungen direkt im DNS zu hinterlegen.

Beim Einsatz eines lokalen Mailservers und Domänencontrollers sind TXT-Records zudem essenziell, um die Vertrauenswürdigkeit von E-Mails zu steuern (SPF) oder Dienste auffindbar zu machen.

Einrichtung der Reverse-Lookup-Zone (IP zu Name)
Für einen reibungslosen Betrieb des Mailservers (Spam-Vermeidung) und die reibungslose Active-Directory-Integration ist eine funktionierende Rückwärtsauflösung (PTR-Records) zwingend erforderlich. Da beide Subnetze (A und B) im Adressraum 172.16.7.X liegen, reicht eine einzige /24-Reverse-Zone.

Code-Snippet
zone "7.16.172.in-addr.arpa" IN {
        type master;
        file "zones/db.172.16.7";
        allow-update { none; };
};
